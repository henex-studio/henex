**Brand name:** HENEX

- **HEN** = Human, Emotion, Nature (the three relational dimensions)

- **NEX** = Nexus (convergence, connection, interweaving)

## 3. Theoretical Logic

HENEX is a practice-based design framework, not an abstract theory. It grew through work across built environments, public services, interface systems and complex delivery.

The core proposition: design is rarely only about making an object, a screen or a space. It is about understanding how people, emotional context and physical or digital carriers come together. HENEX gives this understanding a structure.

### Narrative logic chain

```
Practice
→ Relational work
→ Three relational dimensions (Human, Emotion, Nature)
→ Node-level location (9 nodes)
→ Method recipe (27 combinations)
→ Practice again
```

In plain terms:
1. HENEX comes from long-term design practice.
2. Design practice involves reading, locating and reorganising relationships.
3. HENEX structures those relationships through Human, Emotion and Nature.
4. The nine nodes help identify where a relationship needs attention.
5. A recipe combines one node from each dimension into a practical method.
6. Selected works show how recipes return to practice.

## 4. Three Dimensions

The three dimensions are not separate categories. They work together to describe every design relationship.

### Human — How people understand, decide and act.
Human factors shape how people recognise roles, interpret choices and take action.

| Node | Diagnostic definition |
|---|---|
| Identity | Culture, role, belonging and self understanding. |
| Perception | How people read, sense and understand information or environments. |
| Agency | The ability to choose, act and influence outcomes. |

### Emotion — How experience carries feeling and meaning.
Emotional cues shape how people interpret, trust and remember an experience.

| Node | Diagnostic definition |
|---|---|
| Affect | The immediate feeling tone carried by an experience. |
| Empathy | Support, care and the need to feel understood. |
| Meaning | Value, memory and why an experience matters. |

### Nature — How context, matter and interface shape interaction.
Material and contextual cues shape where experience happens and how contact is made.

| Node | Diagnostic definition |
|---|---|
| Medium | The channel or environment that carries the experience. |
| Matter | The material, visual or physical substance of an experience. |
| Interface | The touchpoint where people meet a system, product or place. |

> **Note:** Node definitions above are diagnostic (what the node is). Page-facing copy uses action-oriented descriptions (what to do when a node needs attention). See Philosophy IA file for page copy.

## 5. Nine Nodes — Action Guidance

These are the "when to use" descriptions used on the live Philosophy page. They complement the diagnostic definitions above.

| Node | When to use |
|---|---|
| Identity | When roles and responsibilities need to become visible. |
| Perception | When clarity, hierarchy or interpretation needs improvement. |
| Agency | When people need clearer control, next steps or decision support. |
| Affect | When atmosphere, tension or first response shapes the experience. |
| Empathy | When pressure, vulnerability or support needs must be recognised. |
| Meaning | When interpretation gives weight to a design choice. |
| Medium | When service, digital or spatial context changes engagement. |
| Matter | When form, texture, image or condition shapes response. |
| Interface | When contact points need clearer feedback or connection. |

## 6. Method Recipes — Logic

A recipe brings three nodes together, one from each dimension, to describe a fuller design situation. It is a practical method for reading and reorganising a specific relationship through design.

- 3 dimensions × 3 nodes each = 27 unique recipes (R01–R27)
- Public recipe IDs: R01 to R27
- Anchors on Philosophy page: #r01 to #r27
- Case study backlinks use format: philosophy.html#r24

A project may use one primary recipe and several supporting recipes. The recipe does not replace the case study. It gives the case study a clear link back to the HENEX framework.

**Example recipe:**
> R24 — Trust & Cooperation Rules
> Agency × Empathy × Interface
> Build trust mechanisms for safe participation and exchange.
> Use when people need to act with confidence inside a marketplace, support system or collaborative service.

## Glossary

| Term | Meaning |
|---|---|
| Dimension | One of the three main relational categories: Human, Emotion, Nature |
| Node | One of the 9 sub-elements within the dimensions |
| Recipe | A practical design method formed by combining one node from each dimension |
| Triad | The combination of three nodes in a recipe (one per dimension) |
| Nexus | Convergence point — where the three dimensions meet to create experience |
| Diagnostic definition | A "what it is" description, used in theory and internal reference |
| Action guidance | A "when to use" description, used in page-facing copy |
